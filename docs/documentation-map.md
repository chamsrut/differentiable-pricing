# Documentation map

What each document is, who may edit it and when, and which one wins when two
documents disagree.

## Classes

| Class | Members | May edit | Update trigger |
|---|---|---|---|
| Automatic entry point | `AGENTS.md`, `CLAUDE.md` | Yes, deliberately, with review | A durable cross-tool rule changes (`AGENTS.md`), or Claude-specific wiring — hooks, subagents, model routing — changes (`CLAUDE.md`) |
| Living state | [project-state.md](project-state.md) | Yes, routinely | Any milestone starts, changes scope, or completes; the "exact next task" changes |
| Active task | `tasks/active/*.md` | Yes, within the task's own scope | The task's plan, gates, or outcome change; on completion, mark `status: Completed` and record the outcome in the decision log and project state |
| Task template | [tasks/TEMPLATE.md](tasks/TEMPLATE.md) | Rarely | The required sections for a task spec change |
| Normative contract | [architecture.md](architecture.md) and the applicable `*-contract.md` files (research, american-crr, american-lsm, pde-numerical, market-state-reconstruction) | Yes, when the underlying method changes | A numerical method, convention, architecture, or interface it governs changes. Prefer appending a new dated/task-numbered section over rewriting a rule that already shipped; never edit a rule to match a later result |
| Append-only decision record | [decision-log.md](decision-log.md) | Append only | A decision is made that a later task must not relitigate. Never edit or delete a past entry; add a new entry and cross-link if a decision is superseded |
| Frozen evidence | `results/*.json`, `figures/*.svg` | Never by hand | Only regenerated by the one designated generator/validator script for that family, from a reviewed raw report |
| Human/public narrative | `README.md`, `CONTRIBUTING.md`, [agentic-workflow.md](agentic-workflow.md), [agent-system.md](agent-system.md) | Yes, freely | Whenever it becomes stale or unclear; no special process, but it must not contradict a higher tier once caught |

## Conflict precedence

When two documents disagree, the higher tier is correct:

1. code, versioned configuration, and frozen evidence (`docs/results/`,
   `docs/figures/`);
2. normative contracts — [architecture.md](architecture.md) and the
   applicable `*-contract.md` files;
3. [decision-log.md](decision-log.md);
4. [project-state.md](project-state.md) and the active task spec;
5. `README.md` and other narrative documentation.

This is not a hypothetical concern: narrative documentation in this
repository has previously fallen behind an implemented task before being
caught and corrected (a prior README section described work later shipped
by task 9C-C2b1 as not yet implemented). That is exactly the failure mode
tier 5 is not allowed to cause — trust the higher tier whenever a narrative
document and a contract, the decision log, or `project-state.md` disagree,
and treat the disagreement as a defect in the narrative document to be
fixed, not as evidence against the higher tier.

## Notes

- The two "Automatic entry point" members are not interchangeable.
  **Neither tool independently discovers both files as automatic entry
  points.** Codex independently discovers `AGENTS.md` and does not
  automatically discover `CLAUDE.md`. Claude Code independently discovers
  `CLAUDE.md` and processes its `@AGENTS.md` import, so both files enter
  Claude's context through the `CLAUDE.md` entry/import chain, not through
  Claude Code separately discovering `AGENTS.md` on its own. Human readers
  begin with `README.md`. Full detail: [agent-system.md](agent-system.md).
- `docs/agent-system.md` documents the *intended* agent architecture,
  including pieces that are planned but not implemented. It is narrative,
  not a contract: nothing in it may be read as evidence that an unimplemented
  piece already exists.
- Auto-generated or tool-local "memory" (any assistant's own persistent
  memory feature) is never a source of truth for project state. It is a
  convenience cache at best; [project-state.md](project-state.md) is
  authoritative. See `agent-system.md`.
- Every local link in every document in this repository is expected to
  resolve. A broken relative link is a defect in the document containing it.
