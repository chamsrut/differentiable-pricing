# Documentation map

What each document is, who may edit it and when, and which one wins when two
documents disagree.

## Classes

| Class | Members | May edit | Update trigger |
|---|---|---|---|
| Automatic entry point | `AGENTS.md`, `CLAUDE.md` | Yes, deliberately, with review | A durable cross-tool rule changes (`AGENTS.md`), or Claude-specific wiring — hooks, subagents, model routing — changes (`CLAUDE.md`) |
| Living state | [project-state.md](project-state.md) | Yes, routinely | Any milestone starts, changes scope, or completes; the "exact next task" changes |
| Task specification | `tasks/active/*.md`, indexed by [tasks/README.md](tasks/README.md) | Yes, within the task's own scope | The task's plan, gates, or outcome change; on completion, mark the spec `Completed` **in place** and record the outcome in the decision log and project state. Specs are never relocated — see "Task lifecycle" below |
| Task template | [tasks/TEMPLATE.md](tasks/TEMPLATE.md) | Rarely | The required sections for a task spec change |
| Normative contract — American neural roadmap | [american-neural-architecture-freeze-v2.3.md](american-neural-architecture-freeze-v2.3.md) | Only by a superseding, explicitly versioned architecture freeze | The American neural-pricer architecture changes. It is **versioned, not amended in place**: a change means a new freeze document (v2.4, v3, …) adopted by its own decision-log entry, which supersedes this one. Never edit a frozen architecture rule to match a later result |
| Normative contract — general | [architecture.md](architecture.md) and the applicable `*-contract.md` files (research, american-crr, american-lsm, pde-numerical, market-state-reconstruction) | Yes, when the underlying method changes | A numerical method, convention, architecture, or interface it governs changes. Prefer appending a new dated/task-numbered section over rewriting a rule that already shipped; never edit a rule to match a later result |
| Append-only decision record | [decision-log.md](decision-log.md) | Append only | A decision is made that a later task must not relitigate. Never edit or delete a past entry; add a new entry and cross-link if a decision is superseded |
| Frozen evidence | `results/*.json`, `figures/*.svg` | Never by hand | Only regenerated by the one designated generator/validator script for that family, from a reviewed raw report |
| Human/public narrative | `README.md`, `CONTRIBUTING.md`, [agentic-workflow.md](agentic-workflow.md), [agent-system.md](agent-system.md) | Yes, freely | Whenever it becomes stale or unclear; no special process, but it must not contradict a higher tier once caught |

## Conflict precedence

When two documents disagree, the higher tier is correct:

1. code, versioned configuration, and frozen evidence (`docs/results/`,
   `docs/figures/`);
2. normative contracts — for the American neural-pricer roadmap,
   [american-neural-architecture-freeze-v2.3.md](american-neural-architecture-freeze-v2.3.md)
   first; then [architecture.md](architecture.md) and the applicable
   `*-contract.md` files;
3. [decision-log.md](decision-log.md);
4. [project-state.md](project-state.md) and the active task spec;
5. `README.md` and other narrative documentation.

This is not a hypothetical concern: narrative documentation in this
repository has previously fallen behind an implemented task before being
caught and corrected (a prior README section described work later shipped
by task 9C-C2b1 as not yet implemented). That is exactly the failure mode
tier 5 is not allowed to cause — trust the higher tier whenever a narrative
document and a contract, the decision log, or `project-state.md` disagree,
and treat the disagreement as a defect in the narrative document to be
fixed, not as evidence against the higher tier.

## Task lifecycle

Every task specification stays at the path it was written to, under
`tasks/active/`, for its whole life. Status is marked **in place** in the
spec's own `## Status` block, and the lifecycle grouping — Active, Completed,
Deferred/on hold, and the archived exploratory line — is
[tasks/README.md](tasks/README.md).

Specs are not relocated into `completed/` or `deferred/` directories, for three
reasons:

1. [decision-log.md](decision-log.md) is append-only, and its entries link task
   specs by path. Moving a file would either break those links or require
   editing entries that may never be edited.
2. `python/tests/test_pde_label_policy_v2.py` opens
   `docs/tasks/active/task-9c-c3-label-policy-v2.md` by exact path, and
   `python/src/differentiable_pricing/american/pde_label_policy_v2.py` names the
   same path — and that module is digest-pinned inside the frozen v2 snapshot's
   executable-source inventory. Moving that spec would break a test, and
   repairing the module would break frozen-evidence reconciliation.
3. A stable path makes an old link from any branch, PR, or review still resolve.

**The directory name `active/` is therefore a location, not a status claim.**
The authoritative status of any task is its own `## Status` block; the index in
[tasks/README.md](tasks/README.md) is the human-readable grouping and must be
updated whenever a task's status changes.

## Digest-pinned documents

Five normative contracts are **content-digest-pinned** by task 9G's frozen
protocol, `configs/american_neural_pilot_protocol_v1.toml`, and enforced by
`scripts/check_american_neural_pilot_protocol.py`, which runs in
`scripts/check.sh` and in CI:

- [architecture.md](architecture.md)
- [research-contract.md](research-contract.md)
- [american-crr-contract.md](american-crr-contract.md)
- [american-crr-dataset-admission.md](american-crr-dataset-admission.md)
- [pde-numerical-contract.md](pde-numerical-contract.md)

**Editing any of them by one byte fails that gate**, because the recorded
digest no longer matches. Repairing the gate would mean editing a frozen
protocol's pinned inputs for a completed, terminal experiment, which is not a
documentation change and is not done casually.

Consequently these five files cannot be revised as part of a documentation-only
change. Where one of them describes the American neural-pricer roadmap and
[american-neural-architecture-freeze-v2.3.md](american-neural-architecture-freeze-v2.3.md)
disagrees, **the freeze wins** by the precedence order above, and the pinned
document is read as the accurate record of what task 9G actually built and ran
— not as the current forward plan. Changing that requires a separate, reviewed
decision about the pinned protocol itself.

## Notes

- The two "Automatic entry point" members are not interchangeable.
  **Neither tool independently discovers both files as automatic entry
  points.** Codex independently discovers `AGENTS.md` and does not
  automatically discover `CLAUDE.md`. Claude Code independently discovers
  `CLAUDE.md` and processes its `@AGENTS.md` import, so both files enter
  Claude's context through the `CLAUDE.md` entry/import chain, not through
  Claude Code separately discovering `AGENTS.md` on its own. Human readers
  begin with `README.md`. Full detail: [agent-system.md](agent-system.md).
- `docs/agent-system.md` documents the *intended* agent architecture,
  including pieces that are planned but not implemented. It is narrative,
  not a contract: nothing in it may be read as evidence that an unimplemented
  piece already exists.
- Auto-generated or tool-local "memory" (any assistant's own persistent
  memory feature) is never a source of truth for project state. It is a
  convenience cache at best; [project-state.md](project-state.md) is
  authoritative. See `agent-system.md`.
- Every local link in every document in this repository is expected to
  resolve. A broken relative link is a defect in the document containing it.
